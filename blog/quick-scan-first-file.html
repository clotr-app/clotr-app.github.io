On device protection, so many hurdles.

Clotr for Windows isn't out yet. I'm testing it on my own PC before it's released, and the cool part is that absolutely none of it's scanning abilities are functional yet. The past few days I've been stuck trying to figure out what's seizing it, and I think I finally got it.

--------------------------------------------------

The Problem (aside from me):

--------------------------------------------------

A Quick scan works in two steps, first it counts the files it can read in Downloads and on the Desktop. Then it opens them one at a time and hands each one to a background reader, which looks for things like passwords, keys and card numbers. All of it happens on and stays on the PC.

The second step broke on the very first file. The app runs under strict security settings, and they keep it off its fast internal pathing, so each file's contents came back slow as a plain list of numbers. The background reader only takes raw bytes, so it refused the list and reset everything. I had the quick scan capped at 50k files, and a folder scan that scans the entire folder. The folder scan broke the same way.

--------------------------------------------------

The fix

--------------------------------------------------

The easy (for now) fix is turning whatever comes back into raw bytes before the reader sees it. From there a folder holding a test file with a fake AWS key finished with "1 thing worth a look". Results then named the file and said it holds an AWS access key, and the key itself never appeared on screen. "Save a copy" on the Results screen read files the same way, so it got the same fix.

--------------------------------------------------

A second bug, found on the way

--------------------------------------------------

I have a lot of projects on my desktop and wanted to see what scanning just that 'folder' would do, a quick scan stops at 50k files, and it counted 49,967. The scan used to go deep into the first big folder it met before looking at anything else, so a file sitting right on the Desktop could be skipped because a project folder came first.

That one was simple once I actually realized it, a really good example of thinking I worked out a solution but didn't account for every exception. The scan now works through folders one level at a time, so anything sitting right on your Desktop or in Downloads gets counted before it ever wanders into the subfolders. It got its own test too, so it can't quietly come back.

Next up is making the scans smarter: a Full scan that reaches as far as an antivirus would, and a Quick scan that only looks at what's changed since your last Full one. One hurdle down, probably quite a few more to go.
