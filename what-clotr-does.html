What Clotr does, and doesn't

I'd rather you check this page than believe it. Every line below names the file, the test or the setting that backs it, so you can read the same source I'm describing instead of taking my word for it.

What Clotr sends

Clotr has no server, and keeps its short record on your device. If you choose to send a message in a chat, it still goes to that AI service as usual. Clotr checks what you type in the page and stores only what kind of thing it found, the site and your choice; it doesn't need an account.

  • Open chrome://extensions, turn on Developer mode, and click Clotr's service worker. Watch its Network tab while you use an AI chat: it stays empty.

  • Read the rule test named "100% local: no network calls, no remote code." It fails the build the moment anyone adds code to the browser extension that could send data out. Clotr for Windows has a test of its own, but its source isn't public yet.

  • Look at the source yourself: detection runs in patterns.js, plain text matching with no AI model and no call to one.

What it costs

Nothing, and there's no account to make it work. The code carries no payment library and no sign-in screen, because there's nowhere for a password to go.

  • Search the source for a login page or a billing call: there isn't one.

  • Clotr is free, at home and at work. I'm drafting a rollout kit for small offices, and nothing is for sale yet. The Clotr for teams page has more.

  • It's free software under AGPL-3.0-or-later: free to use, and free to stay that way, because the license doesn't allow a closed-source fork.

Which sites it watches

Clotr watches 19 AI chat sites the moment you install it, and nothing else, until you say so.

  • The 19 are listed in ai-sites.json, and the extension's permissions, visible on its store listing or in your browser's own extension settings, name each one by address. There's no permission that covers "AI sites in general."

  • Email and chat apps, Gmail, Outlook, Yahoo Mail, Discord, Slack, WhatsApp, Messenger and Microsoft Teams, stay off until you tick them, on the welcome page or in Settings, and your browser asks you to confirm each one. The list is EVERYDAY_SITES in sites.js.

  • Add any other site yourself, one at a time: clicking Protect this site asks your browser for that one address only, never a broader pattern, in popup.js's permission request. The manifest declares that Clotr may ask for one site at a time; it's the per-click request, not the manifest line, worth reading if you want to see the actual limit.

Scam messages

"Is this a scam?" is Clotr's own page: paste a message you got by text, email or chat, and it marks the wording that real scams use, in English or Spanish, and says what each sign means. It never tells you a message is safe, because no list knows every scam, and the message you paste is never sent, saved or logged anywhere.

  • The signs it looks for are plain text matching in scam-signs.js, built from real scam-message research, not a model's guess.

  • Run npm test in the source and scam-signs.test.js runs the signs over more than 200 scam messages in English and Spanish and more than 200 ordinary ones that only look like a scam. Each message has to get exactly the signs written beside it, no more and no fewer.

  • After a scam, or a near miss, Tourniquet can ask before sending money or an ID number for 30 days, then step back down by itself. It's your own setting, stored on your device, never Clotr's to turn on for you.

The code

The browser extension and the developer tools are open source under AGPL-3.0-or-later, and every extension release can be rebuilt from that source, byte for byte. Clotr for Windows is free, and its source isn't public yet, but it runs the same engine.

  • Read it on GitHub: github.com/clotr-app/clotr. Nothing about how Clotr decides what to warn about is hidden, licensed separately or kept server-side.

  • Build the release zip yourself with npm run package, and compare its checksum against the SHA256SUMS.txt published with that release. They match, because the build only ever packages what git tracks.

Check it yourself

Check Clotr yourself in about ten minutes.

  1. Load Clotr, open DevTools (F12), go to the Network tab and tick Offline, or turn off your computer's network entirely. Open a built-in AI chat and paste the test key AKIA4HPQ7XZ2R6TWLJ3N into the message box. The warning still appears, because catching it never needed a connection.
  2. Clone the repository, run npm install, then node --test --test-name-pattern="100% local" tests/rules.test.js. It passes by scanning every file Clotr ships for a network call; comment out a guard in rules.test.js yourself and run it again to see it fail instead.
  3. Check out the tag of a release you've installed, say git checkout v1.4.1, then run npm run package. It writes dist/clotr-<version>.zip and a line for it in dist/SHA256SUMS.txt. Open that same release on GitHub and compare your line against the SHA256SUMS.txt attached there: the same source always produces the same bytes.

What it can't do

Clotr warns and lets you decide; it isn't a filter that blocks anything on its own, and it can't protect what it can't see.

  • It never stops a message by itself. Every warning ends in your choice, and the strictest setting a person, a team or Tourniquet can apply still only asks first.

  • Some sites can remove Clotr's warning from the page. When Clotr detects that, it stops holding messages there so you can still send. You can read about it in the "Accepted limits" section of the security review.

  • It reads text, not images: a picture's hidden location and a suspicious file name get checked, but a password written across a photo of a screen doesn't.

  • No test set covers every scam or every way a detail can be written. If Clotr misses one, or warns about nothing, tell me.
